# H2-RLMS: активная проверка выбора модели

H2 проверяет, можно ли при неизменном строгом критерии C1 сократить стоимость
дополнительной разметки: политики отличаются только порядком раскрытия заранее
скрытых исходов. Прогнозные модели не переобучаются.

**Финальный статус:** H2 закрыта в RLMS-only controlled scope: fixed-1 000
confirmation, Full-RLMS Q1 и CODA bridge завершены. Подробный итог находится в
`report/H2_final_report.md`; границы закрытия — в `report/H2_closure_status.md`.

## Границы модуля

- `src/` — C1-состояние, oracle, политики Q0--Q3 и runner;
- `tests/` — проверки отсутствия утечки скрытых меток и инвариантов обновления;
- `report/exact_oracle.md` — точный малый minimax-эталон и контрпримеры жадности;
- `configs/` — фиксированные параметры пилотов;
- локальные RLMS-входы и результаты экспериментов не коммитятся.

Используется тот же входной формат, что у H1:
`idind,target_year,y,p_baseline,p_logistic,p_hist_gradient_boosting`.
Файл с полным `y` передаётся только `LabelOracle`; политики видят прогнозы,
наблюдаемые метки и публичное состояние. В controlled masking итоговый evaluator
может использовать полный `y` после запуска, чтобы измерить true regret.

## Первый пилот

Зафиксированный начальный режим: RLMS, 20% искусственно скрытых меток, 10 масок,
единичная цена, `ε=0.0025` и один и тот же C1-критерий для `random`, Q0, Q1,
Q2 и Q3.
Внешние baselines Hara, Active Testing и CODA добавлены отдельными адаптерами;
итоговые таблицы находятся в `report/H2_final_report.md`.

## Запуск пилота

```bash
PYTHONPATH=. python scripts/run_rlms_pilot.py \
  --input /path/to/h1_real_input.csv.gz \
  --q-input /path/to/auxiliary_q_predictions.csv.gz \
  --strata-input /path/to/test.csv.gz \
  --config configs/pilot_rlms.json \
  --output results/pilot_runs.csv
```

Вспомогательные вероятности `q` должны быть построены только по прошлому train-
периоду. Для локального RLMS-пилота используется сохранённый H1-файл
`auxiliary_q_predictions.csv.gz`, обученный на age/sex/education; он не использует
скрытые test-метки. Результаты контролируемой маски содержат `true_regret` только
для последующей оценки, а не для выбора следующего запроса.

`run_rlms_pilot.py` также создаёт рядом с итоговой CSV JSON с полными трассами;
для стохастического Hara-adapter он содержит вероятность выбора строки до каждого
запроса. Это адаптация опубликованной Hara-query к бинарному Brier, а не полное
воспроизведение её исходной цели или правила остановки.

`active_testing_brier_adapter` выбирает строку стохастически пропорционально
средней ожидаемой Brier-потере всех кандидатов при auxiliary `q`. Это явная
многомодельная адаптация Active Testing: исходный метод оценивает один model risk
через LURE, чего нельзя смешивать с нашим C1-правилом остановки.
