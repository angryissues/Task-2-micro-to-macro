# H2: подтверждающий RLMS-прогон

Конфиг был зафиксирован после development-сетки: 20% искусственно скрытых
меток, `epsilon=0.0025`, 1 000 случайно зафиксированных строк, единичная цена,
100 новых масок (seed 20261201). Основная выбранная активная политика — Q2;
остальные политики запускались как заранее определённые сравнения. Все методы
останавливались только по общему точному C1.

## Результат

| Политика | Сертификат при бюджете 100 | Средняя стоимость | Ложные сертификаты |
|---|---:|---:|---:|
| Random | 82 / 100 | 90.5 | 0 |
| Stratified random | 68 / 100 | 93.2 | 0 |
| Uncertainty | 36 / 100 | 97.5 | 0 |
| Hara Brier-adapter | 99 / 100 | 82.9 | 0 |
| Active Testing Brier-adapter | 72 / 100 | 92.5 | 0 |
| Q0 | 100 / 100 | 66.8 | 0 |
| Q1 | 100 / 100 | 65.8 | 0 |
| **Q2** | **100 / 100** | **65.6** | **0** |
| Q3 | 99 / 100 | 66.2 | 0 |

При бюджете 200 все перечисленные методы выдали C1-сертификат в 100 из 100
масок. Истинный regret проверялся по полной известной RLMS-когорте только после
выбора; он не передавался политикам.

## Интерпретация и границы

В рамках заранее выбранного controlled RLMS-режима H2 получает подтверждение:
Q2 достигает того же строгого C1-решения существенно дешевле random и сильных
внешних очередностей. Нулевое число ложных сертификатов является проверкой
реализации на этих масках; безусловная корректность C1 следует из конструкции
границ, а не из частоты в эксперименте.

Это не доказывает переносимость на естественные неответы, другие панели или
неравные реальные цены запросов. Hara и Active Testing представлены Brier-
адаптерами очередности; CODA требует отдельного bridge-прогона из-за иной
исходной классификационной цели.
