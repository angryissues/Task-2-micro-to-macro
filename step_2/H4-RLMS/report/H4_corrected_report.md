# H4-RLMS: исправленный анализ (v2)

Этот отчёт заменяет прежние сравнительные выводы P0/P1 и P2. Пересчёт завершён на прежних замороженных прогнозах, без переобучения. Это ретроспективное исправление, а не новая независимая подтверждающая выборка.

## Что исправлено

1. Раньше при выборе точечного запроса алгоритм подсматривал его скрытый ответ, а блок оценивал по худшему возможному ответу. Теперь оба вида запросов оцениваются по всем возможным ответам; скрытая истина доступна только после выбора запроса.
2. В P0 для накопленного индикатора выхода терялась информация об известных единицах занятости в начале пути. Теперь используются точные маргинальные множества допустимых исходов. На полностью известном пути P0 и P1 дают точный результат.
3. Сертификат проверяется до первого запроса; уже достаточная информация не требует оплаты.

## Протокол

Из 6076 подходящих людей детерминированно выбраны 300 по хешу ID: по одному последнему полному трёхлетнему окну, исходно занятые взрослые 18–64 лет. Все люди из test и не входят в обучение моделей. Будущие контрольные годы — 2022–2025; максимальный год исходов при обучении — 2018.
Известные ответы искусственно скрыты с вероятностью 20%; 50 одинаковых масок для всех политик и цен. Цена точки = 1, бюджет = 200, epsilon = 0,0025. Конфигурация correction_v2 задана до просмотра исправленных результатов. Цена блока — сценарное предположение, а не измеренные расходы на опрос.
Цель — накопленный индикатор хотя бы одного состояния незанятости на трёх будущих годовых контрольных точках, с усреднённой квадратичной потерей. Это не дата фактического первого непрерывного выхода между опросами.

## P0/P1: сколько даёт связность пути

На прежних 1000 строках development-маски endpoint и multi-horizon не изменились: G=0,008903 и 0,008398 соответственно. Для first-exit правильный P0 даёт G=0,008072492, P1 — 0,007972370: разница 0,000100122 (около 1,24%). Прежнее G(P0)=0,029972 и вывод о большом эффекте отозваны. При epsilon=0,0025 эта маска не сертифицирует модель ни с P0, ни с P1.

P1 не шире P0, но размер выигрыша зависит от прогнозов и частично известных путей. Ни наличие большого выигрыша, ни выдача сертификата заранее не гарантированы.

## Проверки и границы вывода

Выполнены 291 повторов старых малых конфигураций и 750 запусков основного P2; ложных сертификатов относительно скрытой полной истины — 0. Старые head(n)-конфигурации содержат повторяющихся людей и перекрывающиеся окна, поэтому сохранены как инженерное воспроизведение, а не независимое исследование расходов.
15 автоматических тестов проверяют точные границы на всех 27 публичных состояниях, полностью известные пути, P1 <= P0, совпадение быстрого и независимого скалярного расчёта, minimax-выбор запроса, отсутствие зависимости от нераскрытых ответов, бюджет и остановку.
50 масок — повторы искусственного скрытия на одной фиксированной когорте; это не 50 независимых выборок людей и не популяционный доверительный интервал. Проверка проведена на полных исходах, искусственно скрытых для алгоритма. Неизвестная истина естественных пропусков не восстановлена этим экспериментом. P3 с внешними фактами здесь не проверен.
Практическая польза: можно сравнивать сценарии цены дозапроса и решать, когда выгодно запросить сразу несколько годовых состояний человека. Расчёт не доказывает экономию реальных денег без измерения фактических цен и доступности ответов.
Статус: исправление RLMS annual controlled H4 завершено. Результат условный: небольшой информационный выигрыш P1 и ценозависимая выгода блоков. Это не универсальное положительное подтверждение всей H4.

## Воспроизведение

```bash
python scripts/recalculate_p2.py --input results/real_rlms/h4_frozen_predictions.csv --config configs/p2_correction_v2.json --out /tmp/rlms_h4_correction_v2
python scripts/report_correction.py --results /tmp/rlms_h4_correction_v2 --out /tmp/rlms_h4_report
python -m pytest tests -q -p no:cacheprovider
```

Конфигурация: configs/p2_correction_v2.json. Агрегаты и хеши: results/correction_v2/. Исходные и построчные данные остаются локальными и не включаются в Git.
